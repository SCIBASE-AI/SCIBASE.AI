# Acceptance Notes

This contribution is designed as a distinct, reviewable issue #12 slice.

## Non-Overlap

It avoids the already-submitted broad editor, operation replay, offline conflict, notebook workbench, kernel lease, reference formatting, authorship governance, freeze and recovery, discussion sidebar, autosave recovery, round-trip fidelity, collaborative review decision, task dependency, equation and figure anchor, presence privacy, accessibility, and manuscript evidence-binding submissions.

## Acceptance Proof

- `node test.js` exercises active embargo, identity leak, restricted artifact, private thread, version drift, safe manifest, report rendering, and deterministic fingerprint behavior.
- `node demo.js` emits both blocked and sanitized release packets using synthetic collaboration data.
- `reports/demo.mp4` is generated locally from deterministic SVG frames.
- No credentials, external services, live data, or production systems are used.

## Release Guard Value

Collaborative research editors often pass through a final export step where editor state is collapsed into a package for reviewers or publishers. This guard catches the high-cost mistakes that happen at that boundary: active embargoes, unredacted restricted evidence, author identity leaks in blind review, private comments, stale approved versions, and ambiguous release-clock policy.
